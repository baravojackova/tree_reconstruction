## The main finding from this phase

For each tree, two AdQSM variants are carried: the one whose DBH best matches
the field measurement, and the synthetic median variant `999`. The gap between
them is the measure of how much AdQSM depends on individual segmentation
rather than a universal procedure.

| tree | variant | DBH m | height m | vol selected | vol 999 | difference |
|---|---|---|---|---|---|---|
| B21_S04 | 090 | 0.386 | 29.4 | 2.357 | 2.330 | −1.1 % |
| B21_S10 | 040 | 0.354 | 27.3 | 1.810 | 1.785 | −1.4 % |
| B21_S07 | 080 | 0.580 | 29.9 | 11.580 | 11.348 | −2.0 % |
| B21_S14 | 080 | 0.373 | 25.8 | 2.847 | 2.775 | −2.6 % |
| B21_S16 | 090 | 0.311 | 26.8 | 1.539 | 1.496 | −2.8 % |
| B21_S08 | 060 | 0.344 | 25.3 | 1.410 | 1.355 | −3.9 % |
| B21_S09 | 060 | 0.327 | 27.2 | 2.201 | 2.065 | −6.2 % |
| B21_S13 | 070 | 0.470 | 28.8 | 4.892 | 3.937 | −19.5 % |
| B21_S12 | 100 | 0.277 | 26.2 | 1.028 | 1.449 | +40.9 % |
| B21_S01 | 080 | 0.505 | 28.7 | 7.762 | 11.106 | +43.1 % |
| B21_S11 | 070 | 0.453 | 27.0 | 3.147 | 5.168 | +64.2 % |
| B21_S21 | 070 | 0.481 | 26.3 | 4.565 | 38.596 | +745.6 % |

**The sign of the difference separates the two groups.** Eight trees where the
median lands *below* the selected variant all sit between 1.1 % and 19.5 %.
Four trees where it lands *above* range from 40.9 % to 745.6 %.

Proposed mechanism, consistent with the data but **not yet independently
verified**: when AdQSM fails on a buttressed stem it fails by *inflating* the
trunk — it cannot separate the buttress from the stem and fits a fat cylinder.
Bad variants therefore always overshoot, never undershoot. When they form a
majority, the median jumps up with them.

### Where the median stops being a median

On the worst trees the `999` variant is not an average of the spread — it is a
verbatim copy of one source variant, because the variants split into two
clusters and the median falls inside the larger one.

- **`B21_S11`**: seven variants split 3 vs 4 at 1.3 m —
  {0.448, 0.452, 0.453} against {0.578, 0.696, 0.958, 1.561}. The median is
  0.578399, which is variant 100's own value to six decimal places.
- **`B21_S21`**: five of seven variants are bad. Sorted DBH at 1.3 m:
  0.481 (070), 0.542 (090), 1.360 (100), **1.368 (050) ← the median**,
  1.465 (060), 1.789 (080), 1.839 (040). `999` is a copy of variant 050.

A median is robust against a *minority* of bad values, not a majority. This
needs stating explicitly in the write-up.

**`B21_S21` decision, made deliberately:** the tree has buttresses and its
`999` variant is unusable (DBH 1.368 m, volume 38.6 m³ against a plausible
4.6 m³). The values are being **kept as they are**. Trimming the buttresses to
get a reasonable AdQSM result would make it incomparable with TreeQSM, which
receives the same unmodified cloud. This will be addressed in the evaluation,
not by editing the data.

### Trunk base is extrapolated, not measured

On every tree checked, the AdQSM taper is constant from 0 to 1.3 m — often to
within 0.3 mm. On `B21_S21` this holds for the good variants too (070:
0.481062 at 0 m vs 0.481139 at 1.3 m). The bottom 1.3 m is not measured; it is
carried down from what AdQSM resolved higher up. Two trees additionally have a
hard zero there — see TODO.

## Fix landed this session (committed, verified)

`adqsm_build_median_variant.py` could not build `999` for `B21_S11`, failing
with "taper.txt height grid does not match".

**Cause.** Spike rejection ran per-variant, *before* the grid-equality check.
The 5.6 m artifact had ratio 3.436 in variant 040 (dropped) and 1.763 in
variant 050 (kept, below the 2.0 threshold). Row counts diverged, 25 vs 26.

**Fix**, additive, scoped to this one script:

- `_reject_taper_spikes()` in `tree_geom_utils.py` gained optional `factor` and
  `detect_only` parameters. The shared default stays **2.0**, so
  `adtree_reconstruct_compare.py` and `taper_curve_compare.py` are unchanged.
- `adqsm_build_median_variant.py` now runs two passes: detect failing heights
  in every variant, take the **union**, drop that same set from all variants.
  Grids stay identical by construction.
- `SPIKE_FACTOR = 1.5` in that script only. Justification: genuine trunk taper
  is monotonically decreasing, so real adjacent-row ratios never exceed 1.0
  (verified on `B21_S11` variant 040 — every genuine ratio ≤ 1.000, the two
  artifacts are 3.436 and 9.987). 1.5 leaves 50 % headroom and catches the
  1.763 case.

**Regression checked on all six trees that already had a `999` variant**
(S01, S04, S07, S08, S09, S10): all **byte-identical**. Nothing needed
recomputing. Scratch output left at
`scripts/python/scratch_999_regression/` with
`scratch_999_regression_check.py`.

**Consequence to carry into the evaluation:** variant `999` is now built with a
1.5 threshold while the DBH-matched variant goes through the main pipeline at
2.0. On `B21_S11` the 5.6 m artifact (ratio 1.763, *inside* the
`TAPER_H_LOWER`..`TAPER_H_UPPER` window of 1.3–10.0 m) is therefore excluded
from `999` but present in the comparison variant. The gap between the two is
partly "universal vs individual segmentation" and partly "stricter vs looser
filter". Lowering the main pipeline to 1.5 would mean recomputing all 12 trees.

2. **Apply the TreeQSM acceptance criterion**, fixed in advance:
   lowest `pmdist_trunk_mean` among models whose `branch_m3` is not an outlier
   within that tree's own set, and whose `n_cylinders` fits the ANSYS budget.
   `pmdist_mean` and `pmdist_branch_mean` must **never** be used as selectors —
   both are minimised by the known-degraded fat-cylinder model.

3. **Select the model for ANSYS export per tree** and run
   `export_geom_ansys.py`, which now writes to `ansys_geom/<TREE>/`.

4. **Fix the ANSYS macro keypoint collision first.** `bk.mac` numbers start
   keypoints `1..n` and end keypoints `10000+i`; above 10 000 cylinders the
   ranges collide and ANSYS *redefines* the keypoint, dragging existing lines
   across the crown. Replace the hardcoded `10000` with a parameter derived
   from `n_rad` at lines 99, 103, 109, 185, 227. Line 227 numbers constraint
   equations, not keypoints — handle separately. Line 185 already carries a
   `nutno opravit!` comment. **The ~8000-element budget was measured while the
   macro was broken; once fixed, the real limit can be measured honestly for
   the first time.**

5. **Handle `B21_S21` explicitly in the evaluation.** Its `999` volume of
   38.6 m³ is not a result, it is a documented failure mode. Decide whether it
   enters aggregate statistics, and say so.

## Standing project rules

- **Anti-deletion line at the start of every filesystem-touching Claude Code
  prompt**: do not delete, move, clean, or "regenerate from scratch" any file
  or folder not explicitly named — including for the agent's own sanity-check
  purposes. Clearing `plots/` for a clean comparison is explicitly forbidden;
  use timestamps or a scratch directory. **This has now been violated four
  times.** Keep a manual backup of `plots/` before any session that touches
  the filesystem.
- **Staged workflow**: read-only diagnostic → explicit confirmation →
  implement → diff review → verification against real printed numbers, not
  "it ran".
- **Additive-first**: new variants alongside existing ones; separate cleanup
  passes. Never rename or remove existing columns, filenames or variables
  without explicit instruction.
- **Never hand-edit AdQSM outputs** (`taper.txt`, `BranchStructure.txt`,
  `TreesParams.txt`). Corrections go in the Python that reads them.
- **Never open `volume_results.csv` in Excel** — it rewrites number formatting
  across all rows and breaks string-matched lookups.
- **All four `upsert_result()` copies** must stay header-identical
  (`tree_geom_utils.py`, `import_matlab_results.py`, `qsm_volume_mean.py`,
  `reference_volume.py`). A mismatch caused real data loss once.
- **No TreeQSM library file edits** — workarounds only.
- **Plotting style** lives in `plot_style.py`; paths live in `paths.py`.
- Conversation in Czech, code / comments / Claude Code prompts in English.
- User is experienced in ANSYS, basic in Python — Python scripts and steps need
