### 1.2 `B21_S08` defect found, fixed and verified

`taper.txt` for `B21_S08` carried a diameter of **10.2942 m** at height 0 m (variant
060) and **23.0126 m** (variant 999) instead of roughly 0.34 m. All eight of its
files were affected, so this was not a one-off run failure.

Cause: `_reject_taper_spikes()` iterated `range(1, len-1)` — interior rows only,
because an edge row has no neighbour on both sides. **The first row of every
`taper.txt` had never been checked, by any threshold, on any tree.**
`make_trunk_radius_func()` only drops rows with radius ≤ 0, so a large positive value
passed. `np.interp` then built a frustum in the bottom 1.3 m worth 37.31 m³ / 182.92 m³
— 97.8 % and 99.8 % of the recorded trunk volume.

Fix, landed in `tree_geom_utils.py`:

```python
BASE_ROW_MAX_RATIO = 3.0     # new constant, SEPARATE from the interior SPIKE_FACTOR
# reject row 0 if d[0] > BASE_ROW_MAX_RATIO * d[1]
```

3.0 is chosen physically: field stump/DBH ratios on these trees run 1.34 to 2.08, so
3.0 sits 44 % above the largest real value and an order of magnitude below the
smallest observed defect (29.9×). Simulated across all 186 `taper.txt` files at
factors 1.5, 2.0, 2.5, 3.0, 5.0 and 10.0 — **identical result at every factor**: eight
files flagged, all `B21_S08`.

Verified: regression run on healthy `B21_S16` gave **zero difference across all 5548
rows** before `B21_S08` was recomputed. After recompute, `trunk_m3` went 38.02 → 0.9517
(variant 060) and 183.11 → 0.9147 (999). AdQSM `TreesParams` reports 0.972 / 0.934 —
reassuring, **not validation**. The 72 raw rows and all `n_cylinders` were unchanged.
`.npz` refreshed for both trees. Backup at
`volume_results.csv.pristine_backup_20260909_1910`.

**Known limit of the new filter:** a ratio rule cannot catch a *uniform* inflation of
the whole lower curve, because the ratio stays 1.0000. This failure mode is present in
the production set — `B21_S21` variant 999 has d(0 m) = 1.3682 m and d(1.3 m) = 1.3684 m
against a field DBH of 0.49 m. The only defence is comparison against field DBH.

### 1.4 Buttresses

Stump/DBH diameter ratio:

```
field, 12 trees        1.342  ..  1.747  ..  2.076
AdQSM / AdTree cal     0.9997 ..  1.0000 ..  1.0000
TreeQSM                1.056  ..  1.132  ..  1.237
```

AdQSM never captures the flare, not even partially — zero of 22 healthy files land in
the 1.20–3.00 band. TreeQSM recovers roughly a quarter of it. In absolute terms
AdQSM is **−44 %** at the base, TreeQSM **−34 %**.

The data is not missing: on the `B21_S08` cloud, mean diameter at h = 0.02 m is 52.7 cm
and the maximum extent 72.1 cm against a field value of 69.0 cm; at 1.3 m it gives
38.1 cm against 39.0 cm. AdQSM discards it.

**Definitional caveat that must appear in the text:** the field value is a tape or
caliper measurement of the *outer envelope* of a fluted, non-circular section, while a
fitted cylinder is closer to an *area-equivalent* diameter. Part of the base
discrepancy is therefore definitional. This is why the base row is scored separately
from the five heights above it, everywhere.

Consequence: bending stiffness goes with diameter to the fourth power, so models carry
a median of **11 % of the real base stiffness** (5 % on S09 to 31 % on S12), at the
point of maximum bending moment.

## 2. Decision framework — select on geometry, validate on structure

**Models are selected by geometry and validated by structural behaviour. Never both by
the same thing.** If models were chosen by which best matches the measured frequency,
frequency could no longer validate anything.

Volume must not be a selection criterion: the beeches have no destructive reference, so
picking each method's model to match the other would measure the tuning, not the
reconstruction.

| criterion | source | role |
|---|---|---|
| taper deviation from field | field, 12 trees | selection |
| DBH vs field | field, 12 trees | selection |
| cylinder count | `volume_results.csv` | selection |
| stability within the grid | `volume_results.csv` | selection |
| trunk / branch / total volume | `volume_results.csv` | description |
| frequency, tilt, deflection | structural measurement | **validation only** |

`pmdist_trunk_mean` is admissible as a tie-breaker. **`pmdist_mean` and
`pmdist_branch_mean` must never be used to select** — both are minimised by the
known-degraded fat-cylinder model.

**Root ball is a controlled constant**, derived from the field-measured base diameter,
identical for all models of a given tree. No method reconstructs roots, and TreeQSM
gives a base diameter 12.7–32.4 % larger than AdQSM, so a per-method root ball would
inject a root-modelling difference into the structural results.

### 5.3 Control pair — effect of crown mass

Full method in `Rozklad_frekvence_hustota_vetvi.docx`. In short: recompute the TreeQSM
model with branch density scaled by

```
phi      = V_branch,AdTree / V_branch,TreeQSM
rho*_br  = rho_br * phi
```

so it carries the same branch mass as the AdTree model at unchanged geometry. Then:

```
d_hmota  = f(T*) - f(T)      mass effect, geometry unchanged
d_geom   = f(A)  - f(T*)     geometry effect, branch mass equalised
d_celkem = f(A)  - f(T)      = d_hmota + d_geom
```

Upper bound sanity check: `f(T*)/f(T) ≤ 1/sqrt(phi)`. Exceeding it means the material
assignment is wrong.

**Cheap only if the model can be restarted from the built state** — only the material
constant changes, so 87 % of the time (preprocessing) is avoided. On S16 the solve
alone is ~0.6 min against 4.9 min for a full run. **Verify the macro allows this.**

Branch/trunk separation is available: column index 10 of `geom_*.txt` is branch order,
0 = trunk. Verified on the S07 file: 220 cylinders of order 0 totalling 4.105 m³, and
34 167 of order 1–14 totalling 7.125 m³.
